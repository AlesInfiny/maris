# テスト方針 {#top}

CSR の Web アプリケーションにおけるテストのあり方を示します。

## テスト方針の概要 {#test-policy}

AlesInfiny Maris OSS Edition では、バックエンドの .NET アプリケーションと、フロントエンドの TypeScript アプリケーションを対象にテストします。
各アプリケーションのテストの詳細は、以下を参照してください。

1. [バックエンドアプリケーションのテスト](backend-application/index.md)
1. [フロントエンドアプリケーションのテスト](frontend-application/index.md)

## テストレベル {#test-level}

テストで確認する内容に合わせて、テストレベルを定義することが一般的です。
本稿では、単体テストフェーズと結合テストフェーズに含まれる以下のテストレベルを定義します。
このうち ITb と、これ以外のテストレベルについては、実行方法などを解説しません。

### 単体テストフェーズ {#unit-test-phase}

フロントエンドアプリケーションとバックエンドアプリケーションを、それぞれ個別にテストするフェーズです。
いずれのテストも、コード分析ツールや自動テストツールで自動実行します。
テストは、 CI ツールに組み込んで短時間で実行できるように作成します。

#### UT0 {#ut0}

アプリケーションを構成する部品が、設計通りに実装されているか確認するテストです。
部品単体を対象とします。
部品の外部に依存する箇所はモック化します。

| 対象           | テスト種別 | 検証単位                                                       | 検証観点                                     | 入力ファイル                                                                                                 | 出力ファイル                             |
| -------------- | ---------- | -------------------------------------------------------------- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------------------------------- |
| バックエンド   | 静的テスト | －                                                             | －                                           | ソースコード                                                                                                 | 静的解析結果                             |
| バックエンド   | 単体テスト | クラス                                                         | 論理設計書通りクラスが実装されていること     | 論理設計書、（単体テスト仕様書）                                                                             | 単体テストコード、テスト結果・カバレッジ |
| フロントエンド | 静的テスト | －                                                             | －                                           | ソースコード                                                                                                 | Lint ・型チェック結果                    |
| フロントエンド | 単体テスト | モジュール、コンポーザブル、ストア、サービス、モデル、スキーマ | 画面設計書通りモジュールが実装されていること | 画面設計書、（単体テスト仕様書）、（コンポーザブル設計書）、（サービス設計書）、（ストア設計書の状態遷移図） | 単体テストコード、テスト結果・カバレッジ |

#### 機能内結合テスト ( UT1 ) {#ut1}

UT0 が完了した部品を結合し、機能単位の仕様が実現できているか確認するテストです。
機能内結合テストは、フロントエンドアプリケーションのコンポーネントテスト、画面テスト、画面遷移テストと、バックエンドアプリケーションの Web API テストで構成します。

| 対象           | テスト種別           | 検証単位                 | 検証観点                                                                                             | 入力ファイル                                         | 出力ファイル                                                 |
| -------------- | -------------------- | ------------------------ | ---------------------------------------------------------------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------------------ |
| バックエンド   | Web API テスト       | HTTP メソッド            | 論理設計書通り HTTP メソッドが実装されていること                                                     | 論理設計書                                           | API テストコード、テスト結果、メソッドに対するカバレッジ     |
| フロントエンド | コンポーネントテスト | コンポーネントの設計単位 | UI 、ロジック、子コンポーネントを結合したコンポーネントが成立し、仕様を満たしていること              | コンポーネント設計書                                 | コンポーネントテストコード、テスト結果・カバレッジ           |
| フロントエンド | 画面テスト           | 画面                     | モジュール※を結合した画面が、レイアウト（見た目）を含めて設計書通り成立していること                  | 画面設計書、画面イメージ                             | 画面内結合テストコード、テスト結果、画面のスクリーンショット |
| フロントエンド | 画面遷移テスト       | 画面遷移                 | 共通機能（ルーター、グローバル状態）と結合し、画面遷移を伴うイベントが発火して設計通り処理されること | 画面設計書（イベント、インタラクション）、画面遷移図 | 画面間結合テストコード、テスト結果                           |

※ UT0 の単体テストで検証したモジュール、コンポーザブル、ストア、サービス、モデル、スキーマを指します。

### 結合テストフェーズ {#integration-test-phase}

フロントエンドアプリケーションから Web API 、データベースまでを結合したシステムが、外部仕様どおりに動作するか確認するフェーズです。
単体テストフェーズが完了したものを対象とします。

#### 機能間結合テスト ( ITa ) {#ita}

重要なユースケースについて、フロントエンドアプリケーションとバックエンドアプリケーションの間の結合を、テストツールで自動的に検証するテストです（自動 E2E テスト）。

| 対象                         | テスト種別 | 検証単位     | 検証観点                                                                   | 入力ファイル                   | 出力ファイル                                             |
| ---------------------------- | ---------- | ------------ | -------------------------------------------------------------------------- | ------------------------------ | -------------------------------------------------------- |
| フロントエンド、バックエンド | E2E テスト | ユースケース | 画面から DB まで一気通貫で動かし、ユースケースカバレッジを網羅していること | 要件定義書（ユースケース記述） | E2E テストシナリオ、テスト結果、ユースケースカバレッジ表 |

#### ITb {#itb}

アプリケーションを手動で操作し、フロントエンドアプリケーションとバックエンドアプリケーションの間の結合を検証するテストです（手動 E2E テスト）。
