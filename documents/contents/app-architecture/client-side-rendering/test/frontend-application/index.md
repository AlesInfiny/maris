# フロントエンドアプリケーションのテスト {#top}

フロントエンドアプリケーションでは、以下のテストを行います。
ソースコードのレビューと手動で操作する E2E テストを除き、いずれのテストも開発者のローカル環境と CI 環境で自動実行します。

| テストレベル | テスト名称           | 確認内容                                                                                         | 利用するツール                                  |
| ------------ | -------------------- | ------------------------------------------------------------------------------------------------ | ----------------------------------------------- |
| UT0          | 静的テスト           | 静的解析とレビューにより、不具合の原因となる記述や規約違反、型の誤りがないこと                   | Prettier 、 ESLint 、 Stylelint 、 vue-tsc      |
| UT0          | 単体テスト           | 分岐条件や入力値検証などのロジックが設計どおりに動作すること                                     | Vitest                                          |
| UT1          | コンポーネントテスト | UI 、ロジック、子コンポーネントを結合したコンポーネントの描画と操作時の動作が、仕様を満たすこと  | Vitest 、 Vitest Browser Mode 、 Vue Test Utils |
| UT1          | 画面テスト           | UT0 で検証した部品を結合した画面の描画と操作時の動作が、レイアウトを含めて設計書どおりであること | Vitest 、 Vitest Browser Mode 、 Vue Test Utils |
| UT1          | 画面遷移テスト       | ルーターやグローバル状態と結合し、画面遷移を伴うイベントが設計どおりに処理されること             | Vitest 、 Vitest Browser Mode 、 Vue Test Utils |
| ITa          | E2E テスト           | 画面から DB まで一気通貫で動かし、要求されたユースケースを網羅していること                       | Playwright （自動化するユースケースのみ）       |

## 単体テストフェーズのテスト方針 {#ut-phase-policy}

- 単体テストとコンポーネントテストでは、コードカバレッジを重視します。
- Web API 呼び出しやグローバルな状態など、テスト対象の外部に依存する箇所はモック化します。
- コンポーネントテスト以降は、 Vitest Browser Mode の [Context API :material-open-in-new:](https://vitest.dev/api/browser/context.html#context-api){ target=_blank } を用いて、実ブラウザー上の操作に近い形で検証します。
